## Bugs found and fixed during this session's own review

Since live browser execution wasn't available (see Blockers below), verification was manual/static —
and it did catch two real, would-have-shipped bugs:

1. `#shortlist-container` was originally placed as a sibling **outside** `<section id="view-shortlist">`
   in `proposal_A.html`, instead of nested inside it — the shortlist would never have become visible when
   switching views (it doesn't itself get the `hidden` toggle). Fixed by nesting it correctly (and
   `proposal_B.html` was written correctly from the start once this was caught).
2. The mobile filter panel (`#filters-drawer.is-open-mobile`) is a full-viewport fixed overlay that would
   have covered its own trigger button with no way to close it — a real dead-end for mobile users. Fixed
   by adding a dedicated `#filters-mobile-close` button (visible only while the panel is open) plus an
   `Escape` handler, wired in `app-core.js`.

Also fixed the drawer header label, which was wired to the `table_action` i18n key ("Open"/"Открыть") —
wrong copy for a panel title — by adding a dedicated `drawer_title` key ("Detail"/"Детали") and pointing
both proposal pages at it. Also cleaned up one dead variable (`PRICE_SCORE_PROYECTOS`, unused — the
Proyectos model intentionally has no price factor, per the prompt's own valuation criteria for that
channel), fixed the CSV BOM to use
`String.fromCharCode(0xFEFF)` instead of an embedded literal character (removes any encoding-fidelity
risk), made the selected map point always paint on top (SVG has no z-index; re-sorted draw order so the
selected `<g>` is emitted last), and replaced the `:has()`-only 5-vs-6-column nav-band CSS with an
explicit JS-set class (`nav-band-6`) so it doesn't depend on that selector's browser support.

## Tests performed

- **Static/manual**: full read-through of `app-core.js` twice; brace/paren counts sanity-checked (one
  raw paren-count mismatch was traced to a regex literal `/\([^)]*\)/g` — expected, not a bug); every
  `getElementById` target cross-referenced against both proposal HTML files; dataset field names and
  distinct values (`typology`, `city`, `price_range`, `physical_exhibition`, `service_scope`,
  `canal_secundario`) pulled directly from `data_v3/*.json` via grep before being hard-coded into filters
  — nothing invented.
- **Analytical**: reasoned through the positioning-map collision-avoidance algorithm's worst case (a
  fully collocated cluster) against the golden-angle spiral's growth rate and the realistic score-bucket
  cardinality of the actual dataset (typology × price × exhibition × service-scope × competitive ×
  evidence ≈ dozens of distinct buckets for 169 records) — concluded the 24px/18px minimum-separation
  requirement is comfortably achievable within the plot bounds without hitting the 400-attempt cap or the
  boundary clamps. This is reasoning, not a measured result.
- **Not performed (see Blockers)**: actually opening `tests/test-runner.html` or either proposal page in
  a real browser, the keyboard/drawer walkthrough, the EN/RU visual check, the four responsive-breakpoint
  screenshots, and the CSV-download check the master prompt requires before calling this "done".
